# UI Guidelines

The goal is family resemblance and predictable engineering UX, not identical screens.

Prefer consistency in:

- terminology
- typography and visual hierarchy
- spacing and density
- status presentation
- destructive-action warnings
- progress and loading states
- empty/error states
- keyboard behavior where relevant
- documentation/help entry points

Do not force a native host UI to mimic an Electron application. Technology-specific UX is allowed when it better serves the workflow.
