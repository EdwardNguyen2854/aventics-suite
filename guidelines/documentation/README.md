# Documentation Guidelines

## Ownership

Component repositories own component-specific architecture, build instructions, debugging, release details, and API notes.

The Suite owns cross-component architecture, integration standards, component/capability catalogs, Suite release information, and cross-component workflows.

## Principle

Avoid copying the same documentation into both places. Suite documentation should link to or ingest component documentation where practical.

## Managed component baseline

A managed component should document:

- purpose
- installation/runtime requirements
- key capabilities
- safety/write behavior
- development/build workflow
- release/update behavior when applicable
- troubleshooting entry point
